# 术语表与简单自定义规则技术路线

研究基线：`master bc86fd7`，BabelDOC **0.6.4**。**本轮仅研究，功能未实现**；只新增本文，不修改实现或测试，不读取日常凭据、不调用模型，不开展引擎迁移、macOS 推进或 Windows 验收。

## 1. 路线结论与现有接入点

建议在现有自有请求链内实现：**CSV 术语映射 + 两种字面规则 → 有效配置快照 → 同命名空间缓存 → 请求约束与本地检查 → 用户可见提醒**。先交付全局配置闭环，再增加单篇例外；不建设通用规则引擎。

当前链路为：

```text
settings.js → paperbridge.configuration() → tasks.config()/enqueue()/batch()
    → library.configSnapshot()/describe() + POST /jobs
    → server.configuration()/JobStore.queue() → run() 的 stdin 配置
    → engine._translate() → batching.CostAwareILTranslator
    → deepseek.translate_items()/messages()/request_completion()
```

| 位置 | 当前事实与拟议改动 |
| --- | --- |
| `addon/content/settings.js`、`settings.xhtml` | 现有全局语言/页码、双 provider 草稿。另加术语导入、简单规则编辑与预览；术语保存不调用 `saveKey()`，不绑定凭据保存。 |
| `addon/content/paperbridge.js`、`tasks.js` | `configuration()` 提供非秘密配置，`config()` 深拷贝；单篇、批量、已有结果匹配前绑定有效术语。保留现有入队、找回、显式重试语义。 |
| `addon/content/library.js` | `TRANSLATION_CONFIG_KEYS` 目前只有六项，会丢弃新字段。必须扩展 `configSnapshot()`、`describe()` 的字段传递及 `configKey()` 匹配；否则前端会在到达后端前误用旧附件。 |
| `backend/server.py`、`library_cache.py` | `configuration()` 冻结配置；`queue()` 持久化后将配置深拷贝给 worker。由 `normalize_config()` 统一扩展术语配置、完整 PDF 指纹和段落命名空间，不能各算一套身份。 |
| `backend/engine.py`、`deepseek.py` | `_translate()` 显式传入冻结术语，`DeepSeekTranslator.__init__()` 单独接收，不泄漏给上游构造参数。`translate_items()` 负责命中、缓存及校验，`messages()` 添加约束数据；批量与单段共享此入口。 |
| `backend/batching.py`、`usage.py` | 保留跨页、预处理、应用观察和 cache-only fallback；只补有意保留的结果分类、术语提醒计数，不另建批处理或计费链。 |

`engine.py` 当前关闭自动术语提取；`do_llm_translate()` 从上游 prompt 提取段落后，由自身 `messages()` 重建消息，现有消息只含标题和段落。因此，**仅传上游 `glossaries` 参数既不能证明这里的请求带上约束，也不包含录入、作用域、冻结、缓存隔离和反馈，不算产品能力完成**。无需改上游源码或另起翻译实现。

## 2. 作用域与保存方式

- **首个可用版本只做全局默认表，按 `lang_out` 隔离，独立于 provider。** 同一目标语言切换服务仍使用同一术语，但 provider/model 继续参与缓存身份。不要把简体词表自动用于其他语言；本路线不扩展现有字体或语言交付范围。
- 全局成本最低，适合个人固定领域；跨领域同形词会误用，不能宣称解决上下文消歧。下一阶段按 **`libraryID + 原文 PDF sourceKey + lang_out`** 保存单篇例外：默认继承全局，同源词的单篇条目覆盖全局；另提供“本篇关闭术语”开关。不加学科、分类、作者等多级作用域。
- “论文作用域”实际绑定用户选择的原文 PDF 附件，不按标题、DOI、路径或临时任务 ID 猜配；同论文的其他附件不自动继承。同一附件替换 PDF 可沿用用户选项，源内容哈希变化自然隔离缓存。
- 草稿/已保存词表放在插件数据目录的独立 `terminology.json`，用已有 `PathUtils`、`IOUtils` 原子写入；任务记录只保存解析后的有效快照。无需新数据库、文件监听、全库扫描或同步协议，也不承诺随 Zotero 同步。
- 增加一个无 provider 凭据的本地 `POST /terminology/normalize` 入口，复用拟新增的小模块 `backend/terminology.py` 做解析、合并、规范化和摘要。JS 只展示、保存、传递规范化结果，不自行实现第二套 CSV/哈希算法；单篇覆盖合并也复用此入口。术语内容可能敏感，诊断包不导出词表正文。

## 3. 最小输入、规范化与冲突

**CSV**：UTF-8，可带 BOM，接受 LF/CRLF 与标准 CSV 引号；必需且仅有 `source,target` 两列，目标语言取当前配置，不自动识别编码/语言。

```csv
source,target
self-attention,自注意力
fine-tuning,微调
```

**简单规则**：每行一个操作，字段以实际 TAB 分隔；下例 `<TAB>` 仅用于展示。

```text
keep<TAB>PyTorch
translate<TAB>gradient checkpointing<TAB>梯度检查点
```

`translate` 与 CSV 条目归一为同一种映射；`keep` 表示命中字面内容保留原文，没有目标字段。首版不接受正则、脚本、任意 system prompt、按页/区域规则或“全文首见双语”等需要跨段状态的要求。

规范化与匹配约定：

1. 源/目标做 NFC 与首尾空白裁剪；源词内部连续空白归一为空格，拒绝字段内换行、控制字符、空源词及空译名。保留大小写，不做 NFKC、自动词形还原或简繁转换；大小写别名显式另列。
2. 匹配允许源词间空白差异，但保持字面、大小写敏感；字母/数字/下划线两侧不能嵌入更长单词，如 `net` 不匹配 `network`。中文仍按字面子串匹配。不去断词连字符，不跨段或公式/样式标记拼词。仅规范化匹配视图，`keep` 恢复命中处的原始字符串，缓存键仍使用未改写的输入。
3. 同一作用域的完全相同条目去重；同规范化源词对应不同目标或不同操作，报告行号并拒绝保存该草稿，保留上一份有效配置，不静默“最后一行胜出”。CSV 和规则没有隐含优先级；跨作用域先执行单篇覆盖，再合并。
4. 重叠命中按从左到右、同起点最长匹配，只取不重叠区间；例如先取 `self-attention`，不再对其中 `attention` 应用另一条规则。条目排序后形成有效集合，导入顺序不改变行为。
5. 建议首版上限为有效集合 **256 条、每字段 160 字符、规范化 JSON 64 KiB**，用于限制请求膨胀；这些不是当前已有能力。超限或未知操作明确报错，允许用户修订或显式关闭本次术语，不静默截断。保存失败不影响阅读、旧成果或已排队任务。

有效快照只需 `version`、规范化 `entries` 和 `digest`。`entries` 为 `action/source/target` 字面数据，`keep` 不含目标；摘要由固定 UTF-8、稳定排序与固定 JSON 序列化计算 SHA-256，覆盖规则版本及全部有效条目。文件名、路径、行号、修改时间、作用域来源不参与；相同有效内容可复用，不必因来自全局或单篇而额外隔离。

## 4. 请求应用与受保护文本

1. **只处理已有预处理后的可翻译正文。** `preserve.py` 排除并恢复的图表、独立公式和参考文献区域，以及未选页，不重新送入模型。`{vN}`、`<style...>` 标签/属性是不可改写的结构边界；输入条目不得含这些标记，匹配不得进入或跨越它们。现有数字/引用保留约定也优先于映射：纯数字和明确引文编号不能作为 `translate` 源词，保护冲突只取消该匹配并提醒，不扩大为语义识别框架。现有代码并非自动保护所有正文代码片段，用户可用字面 `keep` 保留其中名称。
2. `translate_items()` 保留原输入与段落 ID，按冻结词表建立命中计划；当前命名空间的缓存命中也须通过结构与规则检查，不合格视为未命中并遵守 cache-only 限制。只将缺失段落的 `translate` 命中映射作为按段落 ID 关联的紧凑 JSON 字段送入 `messages()`，不发送整张词表；系统提示仅增加固定、带版本的应用约定，强调条目值是数据，不能覆盖保护约定或返回格式。
3. `keep` 在自有请求副本中用不会与输入/现有标记碰撞的私有标记暂时代替，每段逐个检查返回标记完整性，随后恢复原字符串。映射只在本次调用局部持有，不能放入两线程共享的可变状态；标记不得进入缓存译文、上游应用文本或片段映射。不是对最终 PDF 做查找替换。
4. 保持现有 JSON/ID/非空译文/公式与样式标记计数检查；私有标记丢失、重复或残留属于结构失败，该段不缓存，不自动重发。若整段所有可翻译文本被 `keep` 覆盖，可不请求模型，记录明确的 expected skip，并在应用观察中保留该分类；不让普通 `unchanged` 判定误报，也不把任意原样响应冒充“有意保留成功”。
5. 对 `translate` 做最低限度的目标字面出现检查。缺失产生**术语未遵守提醒**：有效译文可继续排版、保存和阅读，但该段不写入可复用缓存；不能盲目替换模型输出中的近义词，更不做自动付费纠错。检查只覆盖实际命中的正文，词条没出现在所选页不是错误；目标出现也不等于语义正确或每次出现均正确翻译。

在现有 `quality.json` 增加小型术语摘要（版本/摘要、命中与未遵守计数），由 `server.finish()`、任务记录和任务窗口显示提醒，不保存请求正文或另建质量账本。原有 `complete` 仍只表示应用覆盖证据，不能表示术语/语义验收。**两端完整结果自动复用须排除有术语提醒的结果；`tasks.reviewable()` 也须转为显式检查/重试，避免普通“翻译”操作悄悄再次计费。** 占位符失败仍沿用原有失败/部分成果处理，其他正文与阅读功能不整体失效。

## 5. 入队冻结与缓存身份

- 入队前完成有效配置解析，`library.put()`、`describe()`、`POST /jobs` 使用同一份快照。单篇在结果匹配前绑定术语；批量在循环和首次异步操作前深拷贝全局表及单篇例外表，随后按解析出的原文附件取值，不能在每篇入队时重读可能已修改的设置。
- `server.configuration()` 经 `normalize_config()` 再规范化并核对摘要，不信任客户端自报哈希；持久化完整有效条目及版本/摘要，`queue()` 深拷贝、`run()` 经 stdin 传给引擎。worker 不再读取 CSV 路径或实时设置。前端快照/脱敏逻辑不得静默改写术语字面文本，摘要不一致应只拒绝这份新配置。
- `POST /jobs/{id}/retry` 继续复制**原任务冻结配置**，只重新提供当前凭据，不吸收后来修改的术语。要采用新术语，应经确认新建普通任务，保留旧附件/尝试；响应丢失仍按新指纹找回，不自动重复提交。
- **非空规则**的 `version + digest` 同时进入 `document_identity()` 的完整 PDF 指纹和 `paragraph_namespace()`；provider、endpoint、model、capabilities、语言及原有版本仍保留。`pages` 仍只影响完整 PDF 身份，段落命名空间继续排除它；`document_key` 始终只由源 PDF 内容决定，归属清理方式不变。先对整个有效集合做摘要，不设计逐段词表依赖缓存。
- **缺字段、显式关闭、规范化后空集合统一为无术语。** 保持原系统消息、`PROMPT_VERSION` 和后端身份序列化不变，不因增加空字段使所有旧缓存失效；前端旧记录缺字段同样归一为空。非空路径用独立规则版本，不借修改全局渲染规则版本粗暴清空旧结果。
- 旧 PDF、任务记录、段落行保留可读；旧无术语缓存只可用于无术语任务，非空任务不回退旧命名空间。不补填“当前术语摘要”、不重哈希旧行、不为升级清库；原有未知 provider 的旧段落也仍不复用。带规则的完整 PDF 若缺术语摘要/版本依据，只禁用其自动复用，不删除成果。

当前 `/jobs` 请求上限是 **16 KiB**，`/cache/describe` 是 **8 MiB**。加入快照后，需将 `/jobs` 的显式大小检查及 `body()` 对应调用一起改为例如 **128 KiB**，规范化入口采用相同限额，给 64 KiB 条目和现有信封留余量；不能只增前端字段导致入队 413，也不取消其他接口限额。新模块须进入既有打包清单，但不引入第三方依赖。

## 6. Provider 格式与费用

- 保留 OpenAI Chat Completions 消息及 `{"translations":[{"id":0,"text":"..."}]}` 响应，仍转换为上游需要的 `id/output`；不增加 provider 专有术语参数。DeepSeek 的 JSON 模式/禁用思考、兼容 profile 的显式 `json_mode` 与 `max_tokens` 选择不变；关闭 JSON 模式参数不等于允许任意返回格式。
- 导入、规范化、命中和检查均在本地，不自动抽取术语，不增加模型审核/纠错请求。新增输入 token 大致为各请求“命中词条 JSON + 固定提示 + 保留标记”的总和；现有 **1200 源 token / 12 段**阈值未计入这些开销，`max_tokens` 是输出上限而非上下文预算。小词表与按批子集是首版控制手段，仍需核对所选模型上下文限制；失败不静默丢规则或自动换格式重发。
- 新规则会使本地缓存失配，显式重译可能增加实际请求和费用；更长或变化的消息也不能保证 provider 前缀缓存命中或节省费用。沿用 `MeteredTranslator` 的实际请求/token 账本、SDK 重试关闭及 fallback cache-only；缺失用量/响应仍保留计费未知提示，不虚报零费用。
- 本研究只确认源码接入可行，**没有验证真实服务的术语遵守率、上下文容量或费用**。若后续授权实施，可先用 fake client/禁网管线检查格式；真实短请求和人工语义核对须另获授权，不能以模拟结果冒充完成。

## 7. 最小分阶段实现与核心检查

以下是后续获得实施授权后的拆分，不是本轮完成项。估算以一名熟悉仓库的开发者计，包含少量核心离线检查，不含平台打包验收、真实服务验证或人工翻译质量验收。

| 阶段 | 范围与完成口径 | 估算 |
| --- | --- | --- |
| A | 一个小解析模块、本地规范化入口、全局 CSV/规则保存预览、整条配置冻结及前后端缓存身份；仅有配置传递不算功能交付。 | 1–2 人日 |
| B | 请求子集注入、字面保留/恢复、结构检查与术语提醒、两端安全复用/显式重试；打通导入到可用译文，才是全局 MVP。 | 2–3 人日 |
| C | 附件级覆盖/关闭、批量快照、原配置重试与新配置重译入口；复用 A/B，不新建规则系统。 | 1–2 人日 |

核心检查只覆盖新契约，复用现有质量、缓存与 fake-client 检查，不扩展庞大回归矩阵：

1. BOM/CRLF/CSV 引号、NFC、去重/同源冲突、排序稳定、词界/最长命中、保护标记边界与输入限额。
2. 入队后修改设置、批量中的单篇例外、原配置重试均不漂移；空配置身份与旧基线完全一致，非空规则/provider/语言变化隔离，页码变化仍允许合法段落复用。
3. 前端已有附件匹配、后端完整结果匹配及段落缓存都不误用旧规则；缓存存恢复后的文本，旧文件/旧行保留，摘要不一致不能偷偷改配置。
4. 批量/单段两条入口相同；JSON 模式开/关、IDs、公式/样式与私有标记失败、有意整段保留都分类正确，不污染真实片段应用证据。
5. 未遵守提醒可见、可读但不自动复用或自动付费纠错；故障/fallback/响应丢失维持现有实际用量及显式重试行为。

**可行性：中等工作量，全局闭环约 3–5 人日，加单篇例外共约 4–7 人日。** 主要难点是前后端提前复用的一致性，以及保留标记、质量分类与真实应用证据的衔接，不是增加一个请求参数。无需更换引擎、引入依赖或建立庞大规则框架；词形变化、断词、跨样式词组和语义消歧仍有明确能力边界。
