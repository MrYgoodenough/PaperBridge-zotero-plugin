# PaperBridge 0.3.1 · 自带 Python 版

本次仅发布 macOS Apple Silicon 自带 Python XPI，保持上一版的精简依赖和约 173 MiB 体积。运行时不下载 Python、模型、字体或 tokenizer。

## 文献与译文归属

译文属于论文条目，以 libraryID、论文 key、原 PDF key、译文附件 key 建立本地索引；使用稳定 key，不按论文标题或文件名判断归属。索引保存语言、模型、API 地址、页码、文件状态、规则版本、全文任务指纹和文档 SHA-256。

| 操作 | 行为 |
|---|---|
| 论文进入回收站 | 删除该论文生成的译文附件和实际文件，解除缓存引用 |
| 论文永久删除 | 清除映射；删除无其他论文引用的全文及段落缓存 |
| 删除原 PDF 附件，论文条目仍存在 | 保留译文和缓存，仍可直接打开译文 |
| 删除原 PDF 实际文件，论文条目仍存在 | 保留译文和缓存，原文不可用时直接打开译文 |
| 只从分类移除论文 | 保留译文和缓存 |
| 恢复已删除论文 | 不恢复已经删除的译文，需要重新生成 |
| 相同 PDF 对应多个论文条目 | 每篇管理自己的译文；最后一个引用消失时清理共享缓存 |
| 翻译期间删除论文 | 终止进程后清理缓存，防止任务重新写回 |
| 插件停用期间删除论文 | 下次启动检查归属索引并补做清理 |

旧版 preference 映射迁移为 `translations.json`；删除清理先记录待处理引用，再删除缓存，未完成的处理在重启后重试。原 PDF 删除后，论文条目仍是缓存所有者。旧的两套翻译缓存合并为可按文档清理的段落缓存，避免继续增加无法归属的副本。全局版面模型、宋体提取结果和引擎不随某篇论文删除。

## 当前保存位置

以下以 `<ZOTERO_DATA_DIR>` 表示用户在 Zotero 中配置的数据目录：

- 正式译文：`<ZOTERO_DATA_DIR>/storage/<译文附件 key>/translated.pdf`，由 Zotero 管理和同步。
- 归属索引：`<ZOTERO_DATA_DIR>/paperbridge/translations.json`。
- 全文缓存：`<ZOTERO_DATA_DIR>/paperbridge/.runtime/jobs/<任务指纹>/translated.pdf`。
- 段落缓存：`<ZOTERO_DATA_DIR>/paperbridge/cache/paragraphs.sqlite`。
- 引擎：`<ZOTERO_DATA_DIR>/paperbridge/engine/`，升级仅保留一个引擎。

设置页显示当前数据目录，并提供“数据目录”按钮。工程测试使用 `.runtime/packaged-data/` 中的隔离文献库，没有操作正式库的论文或译文。

## 参考文献不翻译

在生成段落前，按 References、Bibliography、Literature Cited、参考文献等常见标题及单双栏阅读顺序识别参考文献范围，跨页保留，到 Appendix 等后续章节结束保护。参考文献文字不发送 LLM，最终从原 PDF 复制矢量文字与排版；正文中的引用编号继续按原有占位符保留。

旧译文附件仍可手动打开。执行新翻译时不复用旧规则的全文缓存，已有正文段落缓存继续复用。
