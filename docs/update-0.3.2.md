# PaperBridge 0.3.2 源码更新

本版整合可靠任务基础与 Windows 的译文恢复、质量判定和详细进度工作；源码版本不等同于已上传的 GitHub Release。

## 行为

- 回收站、原文缺失及失败重试不由插件永久删除已保存译文；共享论文各自拥有附件，取消一项不影响其他归属。
- 质量依据真实翻译单元的校验与排版应用证据，区分完整、部分、不可用、未知。仅生成 PDF 不算成功；后台完整结果复用还校验记录中的 PDF SHA-256。
- 部分译文明确标记并保留，显式重试复用有效段落缓存，不覆盖旧附件。部分和未知附件可显式打开，但不自动当成完整成果复用。
- 使用统一任务窗口显示启动阶段、进度、段落/缓存计数和用时，提供取消、重试和打开。关窗不取消；再次使用入口可恢复查看。批量只保存，不自动打开阅读器。
- 重试必须由用户显式触发，提示可能重复计费；重启中断或响应丢失不自动重发。配置与密钥分别管理，段落缓存按服务地址与能力隔离。
- 原生构建生成平台/Python 模式独立的 XPI 更新地址与 `dist/updates/` 草稿清单，绑定版本、兼容范围和实际 XPI 哈希；匹配安装包上传后才能发布清单。

## 修改入口

- `backend/server.py`：持久化任务、不可变尝试、PDF 校验及安全进度字段。
- `backend/usage.py`、`engine.py`、`batching.py`：单元证据、阶段进度与失败处理。沿用统一 `quality.json`/manifest，不额外维护第二套 `result.json` 状态。
- `addon/content/library.js`、`tasks.js`：归属、保留、显式重试与保存；`tasks-window.js`、`tasks.xhtml`、`paperbridge.js`：统一进度界面和阅读器入口。
- `scripts/build.py`：原生平台、Python 模式与更新清单。不要把一种模式的清单用于另一种模式，或将未上传的构建结果发布为有效更新。

旧版没有完整质量证据的译文仍可显式打开，但不会自动判为完整缓存。0.3.1 已被永久删除的附件与批注无法凭升级恢复。Windows 历史尝试目录继续读取，新目录使用较短路径，不要求修改系统长路径设置。

macOS 0.4.2 是另一个已发布二进制产物，其公式/批注专属源码尚未进入此分支。本版未声称包含这些功能，亦不替换该发布包；当前宏观结构与验证入口见 `tasks-and-results.md`。
