# 0.3.6 后续工作建议

共享源码为 **0.3.6 候选**；四条 Linux/Windows 稳定通道仍为 **0.3.4**。按个人实用产品安排，不增加企业级治理、冗余框架或引擎迁移。

## 本轮交付边界

- P0-3：最简 NOTICE 与 CPython/native/model/tokenizer 来源证据已绑定实际版本/hash；**完整法律合规仍 unknown**。
- P1-5：隔离原生删除/回收站/恢复、共享归属、真实缓存清理和真进程冷重开；清理不取消任务，结果/映射/未知身份不猜删。
- P1-6：Linux 只达到既有 macOS 的 OpenCV `core/imgproc/imgcodecs/python3` 范围，每种包同源码对照约省 **55.25 MiB**；不引入 XZ、别名恢复、模型删减或进一步 strip。
- 可信映射为独立、版本化 Zotero imported JSON 附件；阅读重算双方 PDF hash、核对 exact keys/parent 和真实页界，不需 Python/API。几何变为逐行 quads，保留行间/短末行空白，schema 1 兼容。
- 原生隔离文件下载不等于真实账号云 metadata 同步；缓存重排/结构 verified 不等于人类双语接受。公开新版本和稳定 feed 仍须另获发布授权。

## 按优先级实施

工作量为熟悉代码的一名开发者的人日估算，不含等待用户审查或账号/发布授权。

| 优先级 | 工作与最小完成条件 | 收益 | 风险与控制 | 工作量 / 可行性 |
| --- | --- | --- | --- | --- |
| **1 · P0** | 发布前闭环剩余许可证义务：确认 Windows/native/static 组件归属，决定 GPL/AGPL/Berkeley DB 对应源码和 notice 的交付方式；结论仍不明的逐项记录 | 使公开分发有明确依据，比增加功能更重要 | NOTICE 不代表完整法律审计；先查固定实际构建，不为了许可问题擅自换引擎/删功能。必要时请权利人/法律人员确认 | **1–3 日起，可能等待外部答复；技术核实高，最终法律结论有条件** |
| **2 · P0** | 对已有两篇所选页做人类双语/视觉接受；再补一个真实公式页和一个表格/图表页，记缺陷并直接修当前链路 | 最直接判断“是否值得每天用”，发现语义、阅读顺序和公式排版问题 | 结构完整/可高亮不能证明翻译正确；先用已有输出零费用审查，新翻译请求须另获费用授权 | **已有样本 0.5–1 日；新增样本/修复 2–4 日；高，依赖审查与请求授权** |
| **3 · P1** | 收尾 Windows 旧版升级与 UI 专项：两种模式 0.3.4→0.3.6、任务/缓存/虚拟凭据保留、诊断/凭据边界，实际选区/批注生成新 note 与回链，100%/150% 系统缩放 | 避免“新装能用、老用户升级出问题”；完成上一轮未验收范围 | 本轮映射/清理通过不能冒充这些专项；只用停机备份和隔离 profile，不碰日常 NSS、不同版本各核 hash | **1–2 日；高** |

如果确有兼容服务需求，指定 endpoint/model 并另授权后，安排 **0.5–1 日** 的短检查和一个受限片段；格式通过不等于长任务可靠。繁体/日文、扫描 OCR、本地模型与 Windows ARM64 依据真实痛点择一，不同时展开。

## 暂不推进

- BabelDOC 固定 **0.6.4** / PyMuPDF **1.26.7**；新版迁移低优先级，**不列为 TODO**。
- macOS 专属源码未取得，不合流、不反向提取、不重建覆盖已有 0.4.2 发布物。
- Linux 已达到用户要求的同 macOS 修剪程度，暂不进一步精简；不再列 XZ/strip/别名恢复为下一步。
- 任意段落局部重译/增量排版、精确原译批注同步仍是高成本研究，不能用选页新任务或猜坐标复制冒充完成。
